## 1. Executive Summary

**UltraThink is one product shipped as two tiers**:

- **UltraThink Core** — the private workflow at `<local-ultrathink-core>`. Contains every subsystem: skill mesh, memory, code intelligence, Tekiō adaptive learning, hooks, dashboard, auto-memory, MCP fleet (5 servers), and proprietary domain skills.
- **UltraThink OSS** — the public, open-source subset at `<local-ultrathink-oss>` and `github.com/InuVerse/ultrathink`. Ships the skill mesh (minus a handful of proprietary skills), memory, hooks, dashboard, and Codex-aware integration. Excludes code-intel and Tekiō by design.

The OSS repo is **not a fork or rewrite** — it is a curated downstream subset. On every shared file inspected, Core and OSS are currently byte-identical. This is the correct model; the risk is keeping it that way as Core evolves.

### Headline findings

- **Core/OSS parity is currently tight.** `memory-auto-save.sh`, `memory/src/memory.ts`, `prompt-analyzer.ts`, all 14 migration filenames, and all 20 dashboard API directories are byte-identical across tiers. The two repos are in sync.
- **A previous critical issue turned out to be false.** Both tiers already block `*.env*` capture at `memory-auto-save.sh:72` (`SHOULD_SAVE=false`). The AM-1/P1-1 "credential leak" finding from prior audits was based on stale reading — both tiers are patched.
- **Superpowers fiction only exists in Core.** Core `CLAUDE.md:38-49` and `CREDITS.md:14-18` still claim `obra/superpowers` was merged. OSS `CLAUDE.md` is clean of that claim. This is a Core-only documentation drift issue.
- **OSS has its own identity drift.** The OSS `README.md:40` advertises **"125+ skills"**; the actual count in `.claude/skills/_registry.json` is **388 skills**. OSS `CLAUDE.md:14` says **"370+ skills"** — also wrong. Public-facing claims are stale.
- **Tekiō and code-intel are Core-exclusive and should stay that way** — but the consequence is that the `prompt-analyzer.ts` (shared, byte-identical in both tiers) contains no Tekiō hooks on either side. If Core ever wires Tekiō into prompt-analyzer, a parity decision has to be made.
- **OSS ships only the `vfs` MCP server**; Core ships 5 (vfs, agora, code-intel, vibecli, stitch). OSS has no `code-intel/` directory but its root `package.json` still lists `code-intel` in workspaces (needs verification — may be drift).
- **Neither tier has meaningful test coverage.** Both ship the same 3 test files (`tests/prompt-analyzer.test.ts`, `hooks.test.ts`, `session.test.ts`). ~16k TypeScript files, ~3 test files.

## 5. Drift Risks (where parity is fragile)

### DR-1 — `prompt-analyzer.ts` is the biggest parity bomb [BOTH]
1929 LOC, 23 functions, 10 concerns, byte-identical across tiers. Any future Core change (e.g. wiring Tekiō scoring, adding code-intel result injection) will either break parity or leak Core logic into OSS. **This file needs an explicit tier-boundary convention**: a pluggable adapter pattern where Tekiō + code-intel integrations live in Core-only modules that the shared analyzer imports via optional registry. Severity: **High**.

### DR-2 — `package.json` workspace fiction in OSS [OSS]
OSS root `package.json:10` still lists `code-intel` in `workspaces`, and scripts `codeintel:build` (line 27) / `codeintel:index` (line 28) still invoke a directory that does not exist in OSS. Running `npm install` in a fresh OSS clone will either fail or silently no-op. Severity: **High** for OSS credibility.

### DR-3 — Skill registry drift (393 vs 388) is undocumented [BOTH]
The 5-skill delta between tiers has no manifest. There is no `.claude/skills/_oss-excluded.json` or equivalent. Adding/removing a skill in Core with no reflex in OSS is the most likely source of silent drift. Severity: **Medium**.

### DR-4 — Shared hook files have no CI check for byte identity [BOTH]
`memory-auto-save.sh`, `memory/src/memory.ts`, `prompt-analyzer.ts`, and migrations 001-014 are currently identical by luck + discipline. There is no script that asserts `diff core/X oss/X == empty` as a gate. Any hotfix applied to one repo but not the other creates silent divergence. Severity: **High**.

### DR-5 — OSS public skill count claims are demonstrably false [OSS]
- `README.md:40` — "**125+ domain skills**"
- `README.md:152` — "**125+ skills**"
- `CLAUDE.md:14` — "**370+ skills**"
- Actual (via `_registry.json`): **388 skills**

A new OSS user who reads the README and runs `jq '.skills | length' .claude/skills/_registry.json` immediately catches a 3× discrepancy. First-impression trust destroyed. Severity: **High** for OSS.

### DR-6 — Documentation drift is asymmetric [CORE]
Core `CLAUDE.md:38-49` and `CREDITS.md:14-18` still claim `obra/superpowers` is merged. OSS `CLAUDE.md` is clean. Backporting is the wrong direction here — the fix is to delete the Superpowers claim from Core, not propagate it to OSS. Severity: **High** for Core identity.

### DR-7 — Tekiō bug (`wheelSpin` counts active, not cumulative) is Core-only by definition [CORE]
`memory/src/adaptation.ts:316, 353, 538`. No OSS impact. Fix in Core only. Severity: **High** (Core).

### DR-8 — OSS `memory/scripts/memory-runner.ts` likely lacks identity+wheel commands [OSS]
Core `memory-runner.ts` routes `identity`, `wheel-turn`, `wheel-learn`, `wheel-stats`, `wheel-list`, `conflicts`, etc. If OSS's copy (not diff-checked in this pass) still routes them, invocations will fail at import time. If it doesn't, the public CLI contract is smaller than Core's. Either way, there's a documented CLI delta that needs explicit tier treatment. Severity: **Medium** (OSS).

## 9. Closing Assessment

**UltraThink as a two-tier product works.** Core and OSS are in genuine sync on the shared layer, and the tier boundary — Tekiō and code-intel stay private, everything else ships — is coherent.

**The three biggest threats are not bugs but process gaps:**

1. **No parity discipline mechanism.** Byte-identical today is luck, not a guarantee. The moment Core patches `memory.ts` without backporting, OSS becomes a stale fork. There is no CI gate, no sync script, no shared-changelog, no tier ownership doc.
2. **OSS is publicly claiming things that aren't true.** "125+ skills" when there are 388 is a first-impression disaster. `package.json` referencing a `code-intel` workspace that doesn't exist will break clean clones. OSS cannot be credible as open-source while its own metadata lies.
3. **The shared `prompt-analyzer.ts` is a ticking drift bomb.** It will grow. When it grows to support Tekiō or code-intel injection, either parity breaks or Core logic leaks into OSS. An explicit adapter pattern is needed before the next feature lands on it.

**Core scores 66/100. OSS scores 62/100. Shared layer scores 70/100.** The path to 85+ on both tiers is not more features — it is parity discipline, honest public docs, and the 22 shared-layer issues above.

**Unified headline**: UltraThink is a real two-tier product with genuine sync — today. Tomorrow is the question the improvement plan answers.
